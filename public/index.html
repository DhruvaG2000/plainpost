LOCAL CONNECTION

Mail connections

Connect Gmail with IMAP and SMTP using a private home-directory config, just like Mutt.

b4 relay

Send plain-text submissions through a verified relay identity. Read public threads with lore and keep drafts in this browser tab.

Set B4_RELAY_URL and B4_RELAY_FROM in .env on the Plainpost host, then restart.

Gmail IMAP + SMTP setup
  1. Enable 2-Step Verification in your Google Account, then create an app password named Plainpost. Use that 16-character password, not your normal Google password.
  2. In the Linux terminal that runs Plainpost, run npm run config:init. Edit this private file:~/.config/plainpost/mail.conf
  3. Set imap_user to your Gmail address and imap_pass to the app password. Keep smtp_pass = $imap_pass. On Linux, protect it with chmod 600 ~/.config/plainpost/mail.conf.
  4. Click Reload config & connect. This checks both IMAP and SMTP login without sending mail. No server restart is needed.

Existing static ~/.muttrc and Mutt/NeoMutt home configs are also recognized when there is no Plainpost config. WSL uses your Linux home; a headless board uses the service user’s home.

Gmail IMAP is already enabled for personal accounts. If app passwords are unavailable, check your account policy: managed accounts, Advanced Protection, and some 2-Step Verification configurations restrict them. Google’s app-password help.

Passwords stay in your private server-side config and are never returned to the browser. Disconnect ends local sessions; it leaves your config intact. Revoke the app password in Google Account to disable it.

Optional: Google OAuth

For accounts that cannot use app passwords, the existing OAuth option is still available. Enable Gmail API in Google Cloud, create a Web application OAuth client, register http://localhost:4819/auth/callback, and set GOOGLE_CLIENT_ID and GOOGLE_CLIENT_SECRET in .env. Restart after changing .env.
